# 3. JWT и внутренние полномочия

Статус: принято.

Booking Service подписывает RS256 JWT локальным приватным ключом. Gateway и Hotel Service получают только публичный ключ. Токены пользователей имеют аудиторию `hotel-booking-api`, роли USER/ADMIN и срок один час. Служебный токен имеет аудиторию `hotel-service`, субъект `booking-service` и scope `rooms:write`; он не принимается внешним Gateway.

Проверяются подпись, срок и issuer; роли разрешены только пользовательской аудитории. Внутренние полномочия выдаются только ожидаемому служебному субъекту. Административная роль сама по себе не разрешает резервирование и освобождение внутренним API. Эти маршруты также закрыты в Gateway. Регистрация не принимает поле роли.

Владение бронью проверяется в Booking Service по субъекту токена. Чужой идентификатор возвращает 404. Пароли хешируются BCrypt; удаление пользователя логическое, чтобы сохранять историю. Отключённый пользователь не может войти или выполнять операции бронирования. Изменения ролей отражаются в новых токенах; уже выданные роли действуют до истечения JWT.

Ключи создаёт локальный скрипт с ограниченными правами файлов. Приватный ключ и рабочие токены в репозиторий не входят. Тесты создают временные отдельные ключи. Учётные записи предзаполнения предназначены для локальной демонстрации и отключаются через DEMO_ENABLED.
