# 2. Повторы и блокировки

`Idempotency-Key` уникален для пользователя. В Booking сохраняется SHA-256 параметров запроса. Повтор возвращает прежний результат, изменение параметров возвращает `409 IDEMPOTENCY_CONFLICT`.

Hotel связывает операции по `bookingId` и блокирует строку `reservation_guard`. Выбор по `(times_booked, id)`, проверка дат и запись резерва выполняются вместе. Изменения каталога используют ту же блокировку, поэтому записи Hotel выполняются последовательно.

Отмена неизвестного `bookingId` сохраняется как `RELEASED`, чтобы поздний запрос не создал резерв. Повторное освобождение не меняет счётчик.

Техническая компенсация уменьшает `times_booked`, пользовательская отмена сохраняет его значение. `available` отвечает за вывод номера из эксплуатации, занятость по датам хранится в календаре.
