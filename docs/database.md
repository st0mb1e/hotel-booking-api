# Схема данных

Базы независимы и создаются Flyway. Hibernate запускается с `ddl-auto: validate`. Ссылки между сервисами передаются как идентификаторы. Межбазовых внешних ключей нет. H2 хранит данные в памяти до остановки процесса.

## Booking Service

| Таблица | Основные поля и ограничения |
|---|---|
| `users` | `id`, уникальный `username`, BCrypt `password`, роль USER/ADMIN, флаг `active` для логического удаления |
| `bookings` | UUID `id`, FK `user_id`, выбранный `room_id`, фильтр `hotel_id`, `auto_select`, даты, статус PENDING/CONFIRMED/CANCELLED |
| Поля идемпотентности в `bookings` | `request_key`, SHA-256 `fingerprint`, уникальность `(user_id, request_key)` |
| Восстановление в `bookings` | `failure_code`, `cancellation_reason`, `compensation_pending`, число попыток и `next_compensation_at` |
| Служебные поля | Время создания/обновления и оптимистическая `version` |

Индексы обслуживают историю пользователя, поиск зависших PENDING и очередь компенсаций. Проверка `start_date < end_date` закреплена в схеме. Будущая дата заезда и максимальный срок проживания проверяются до создания брони. При автоподборе `room_id` остаётся пустым до получения ответа Hotel, но компенсация уже может выполняться по UUID.

## Hotel Service

| Таблица | Основные поля и ограничения |
|---|---|
| `hotels` | `id`, имя, адрес, флаг логического удаления |
| `rooms` | FK `hotel_id`, уникальность `(hotel_id, number)`, эксплуатационная доступность, неотрицательный `times_booked`, логическое удаление и `version` |
| `room_reservations` | PK `booking_id`, FK `room_id`, даты, статус RESERVED/RELEASED, причина отмены, время создания и `version` |
| Параметры выбора в резерве | `auto_selected` и `hotel_filter_id` позволяют обнаруживать повтор UUID с другим запросом |
| `reservation_guard` | Одна строка с `id = 1` для атомарного выбора, идемпотентности и изменений календаря |

Активный резерв обязан содержать номер и корректный диапазон дат. У RELEASED без предшествующего резервирования номер и даты могут отсутствовать: это запрет на запоздалое выполнение команды. Индекс `(room_id, status, start_date, end_date)` обслуживает календарь, индекс доступности и счётчика используется для рекомендаций. Миграция V2 добавляет поля атомарного автоподбора и разрешает такую запись об отмене.

Календарь и `available` решают разные задачи: свободный по датам номер может быть выключен на ремонт. Пользовательская отмена освобождает календарь, сохраняя исторический счётчик. Техническая компенсация также откатывает счётчик. Логическое удаление отелей, номеров и пользователей сохраняет связи с историей.
