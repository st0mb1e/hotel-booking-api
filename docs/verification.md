# Проверка требований

Команды выполняются из корня репозитория. Для модульных и интеграционных JUnit-тестов достаточно JDK 21. Maven Wrapper загрузит зависимости. Каждый тест использует отдельную H2 или локальный HTTP-сервер со случайным портом. Общие тестовые RSA-ключи находятся в test-jar модуля `common` и отсутствуют в runtime-зависимостях сервисов.

```sh
./mvnw clean verify
./scripts/run-local.sh --skip-build
python3 scripts/smoke-test.py
python3 scripts/load-test.py
python3 scripts/integration-test.py
./scripts/stop-local.sh
```

Если стандартные порты заняты:

```sh
DISCOVERY_PORT=18761 HOTEL_PORT=18081 BOOKING_PORT=18082 GATEWAY_PORT=18080 ./scripts/run-local.sh --skip-build
API_URL=http://127.0.0.1:18080 python3 scripts/smoke-test.py
API_URL=http://127.0.0.1:18080 python3 scripts/load-test.py
HOTEL_API_URL=http://127.0.0.1:18081 python3 scripts/integration-test.py
./scripts/stop-local.sh
```

## Сценарии

- Smoke: JWT, маршрутизация и discovery, CRUD брони, повтор внешнего запроса, восемь конкурентных попыток занять один номер, отмена, автоподбор, роли и закрытые внутренние пути.
- Нагрузка: 32 одновременных автоподбора на разные даты в отеле из четырёх одинаково доступных номеров дают `8/8/8/8`. 16 запросов на одни даты дают четыре разных номера и 12 конфликтов.
- Сага: дополнительный Booking работает с настоящим Hotel через прокси. Ответ успешного резервирования заменяется на 503. Проверяются отмена без известного `roomId`, освобождение по UUID и восстановление счётчика. Во втором сценарии освобождение тоже временно недоступно. Сохранённая задача выполняется обработчиком после восстановления связи.
- JUnit: задержка тела после заголовков, ограниченные повторы, отдельная цепь компенсаций, повтор UUID с разными номерами, параллельный автоподбор, отмена до подтверждения, даты, CRUD, JWT, единые 404/503 ошибки Gateway и корреляция.

## Соответствие критериям

| Критерий | Где проверяется |
|---|---|
| Планирование занятости | `AvailabilityService`, `RoomAllocationTest`, `RoomReservationTest`, `load-test.py`: атомарный выбор, порядок счётчик/id, календарь, конкуренция и идемпотентность |
| Согласованность сервисов | `BookingService`, `BookingRecovery`, `HttpHotelClientTest`, `integration-test.py`: локальные транзакции, компенсация, Retry/Timeout/Circuit Breaker |
| Booking CRUD | `BookingApiTest`, `BookingIdempotencyTest`, `BookingCancellationTest`: своя история, пагинация, даты, права, ключи повторов и отмена |
| Hotel CRUD и аналитика | `HotelCatalogTest`, `RoomAllocationTest`: CRUD, фильтрация и сортировка, занятые ночи и процент загрузки |
| Gateway и Eureka | `GatewayIntegrationTest` и smoke: маршруты `lb://`, передача JWT и requestId, поиск адресов |
| Безопасность | Проверка JWT во всех бизнес-сервисах, методные `@PreAuthorize`, раздельные пользовательские/служебные аудитории, 401/403 |
| Интеграционные тесты | Конкурентные JUnit-тесты плюс HTTP-проверки с настоящими сервисами и управляемыми отказами |
| Схема БД | Flyway, [описание данных](database.md), ограничения, связи, индексы и ADR |
| Демоданные | ADMIN и USER, два отеля, несколько доступных номеров и номер вне эксплуатации. Отдельные наборы данных создаются сквозными тестами |
| SOLID и DRY | Интерфейс клиента Hotel, отдельные оркестрация и транзакции, общая security-конфигурация, отдельные DTO по предметным областям и общий тестовый fixture |
| Стиль | Spotless проверяется в `verify`, пакеты api/service/domain/repository/config |
| Ошибки | `ApiExceptionHandler`, `GatewayExceptionHandler`, `GatewayErrorWriter`: единый ApiError и статусы |
| Логи и трассировка | JSON, `X-Request-Id`, `bookingId`, события саги и повторы. Идентификатор проверяется тестами шлюза |
| Документация | Архитектурная схема в README, описание запуска/API, схема данных и четыре ADR |
| Поддерживаемость тестов | Общие fixture, независимые H2, случайные порты, управляемый HTTP-прокси и автоматическая остановка дополнительного процесса |

Скрипты рассчитаны на локальные демоданные. Дополнительный Booking Service и прокси останавливаются в `finally`. Тестовые брони освобождаются. Отели удаляются логически, записи пользователей и истории остаются до перезапуска H2.

## Форматирование

Для исправления форматирования Java-файлов нужно выполнить `./mvnw spotless:apply`. Проверка стиля входит в `./mvnw verify`.
